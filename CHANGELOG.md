# Changelog

## Unreleased

- Beginner and expert levels next to quick and full mode: beginners get one step at a time in plain
  words and paste the Terminal output back; `fcwm run` ends with a short summary block made for that
  (each film's QA result and fixes, file paths, the error, the next step).
- Established engines first: 3-D now runs in HyperFrames with three.js (`fcwm new --3d`, MIT, copied
  into the film or added at render time), and music-driven films get a synthesized score in HyperFrames
  (`--score`: `beats.json` plus `audio/score.py`; `fcwm render` runs it and mixes `audio/` to -14 LUFS /
  -1 dBTP under the picture). motion-reel (a small vendored toolkit) is offered only on request or for
  its experimental path tracing, and is never called an FCWM engine.
- Chat hand-off: two replies (the ZIP link and the questions first, the commands only after the user
  pasted the real path), the first-time command when unsure, and one folder per requested format.
- Composition checks in every full render and `fcwm qa` (`qa/composition.mjs`): an empty first frame,
  9:16 content that is small or sits high, scenes copied 3 s apart, and a picture that stands still
  (1.5 s or 40 % of the film). Each FAIL prints its fix; `film.json` `allowEmptyStart`, `allowRepeats`,
  `allowStill` or `composition: false` opt out. Calibrated on the 0.4.0 eval films.
- Skills: five first-draft rules tied to those checks (hook on frame 0, fill 9:16, every scene new,
  always moving, sound).
- GitHub Actions render (`--cloud`): a temporary repository per render, deleted after the download
  (asks once for the `delete_repo` permission); a failed render keeps it for its log. `--public` uses a
  public repository (free Actions minutes, visible while it exists); `--repo <name>` keeps one named
  repository and deletes only the run's artifact.
- Chat apps hand over the film as a direct ZIP download link, never a pointer to a file library.
- Mac test fixes (Apple M4, 2026-11-01):
  - The one-line installer sets up the whole render toolkit on the first run (`fcwm run --full`):
    FFmpeg, uv, Chromium, HyperFrames and its Chrome, Manim and Blender's bpy (Pango on Linux), each
    only when missing. `fcwm setup` installs the same toolkit (`--list` only shows it); it used to only list.
  - Engines HyperFrames, Lottie, motion-reel, Manim and Blender are `ready`; path tracing stays experimental.
  - `fcwm new --title` puts the title on screen (HyperFrames starter), and a long title shrinks to fit.
  - `render --check` fails when text stays off the frame (`text_off_frame`), with the full report in
    `render/check.json`; HyperFrames reports it only as info.
  - A full render rebuilds the contact sheets from the finished video, so they never show an older check.
  - `doctor` fails when Playwright's Chromium is not downloaded.
  - `qa --determinism` on motion-reel accepts GPU rounding noise (frames at 50 dB PSNR or more).
  - Path-traced stills have no 30-second screenshot limit; the motion-reel starter no longer loads
    screenshots that are not there.
  - Skills: never try to render inside a chat app's sandbox, and never assume the user's OS.
- Evals (`evals/`): five reference tasks (promo, chart, lyric clip, logo sting, 3-D product) and a scorer
  that renders each model's films and records render, QA, determinism, format and duration next to the
  judged visual scores; `node evals/run.mjs report` writes one table per release. First comparison of
  three Claude models on three tasks in `evals/results/0.4.0/`.
- ChatGPT Work install guide (`docs/install-chatgpt.md`): marketplace import or ZIP upload.
- Install from a link (`INSTALL.md`): one sentence for any agent; in ChatGPT Work it starts with `@Plugin Creator`
  and rebuilds the plugin file by file, checked against `plugin-files.json` (every plugin file with its
  SHA-256, regenerated by `npm run inventory` and checked by `npm run validate`), then packs and saves it.
- `INSTALL.md`: install by pasting the repository link into any agent (ChatGPT Work, Codex, Claude,
  Cursor, Gemini); the agent follows it with its native plugin or skill installer. README carries the prompt.
- HyperFrames films that import `./lib/fcwm/` without carrying it (hand-off from a chat app) get the lib
  at render time.
- `lib/chart.js`: bars that grow without overshoot, value labels that show only the final value as the
  bar lands, round axis ticks, a count-up that matches the bar, lines that draw on. Tested.
- Every new film carries a placeholder face (Inter, OFL-1.1, Latin and Latin Extended) in `fonts/`, so
  text renders the same on every machine and offline; HyperFrames starters load it as `Display`,
  motion-reel films as `Display` and `UI`. Replace it with the user's typeface.
- motion-reel films get FCWM's blocks in `lib/fcwm/` like HyperFrames films, and
  `templates/motion-reel-score/score.py` is a minimal synthesized score (kick on every beat, soft pad)
  on the film's own grid.
- Skills, from what the eval runs showed models missing: a signature sheet for every lib block
  (`directing-motion-films/references/lib-api.md`); craft rules for the first frame, the hook, 9:16
  composition, honest numbers, ghosting and repeats; which contact sheet to score, silent films, what
  `--check` exit code 2 means, `--at` in seconds; quick mode runs its own rounds and shows the user once.
- The pipeline log says "not needed, skipped" instead of a bare "skip:".

## 0.3.0 (unreleased)

- Blender engine (experimental, tier restricted: GPL-3.0): the official bpy module from PyPI (bpy 5.2.3,
  Blender 5.2 LTS) runs headless through `uv run --with`, no app install. `fcwm new <film> --engine
  blender [--alpha]` starts from a neutral studio scene built in `build(scene, film)`; Cycles with a
  fixed seed, adaptive sampling off and metadata stripped from frames, so a frame renders the same twice
  (checked). GPU (Metal, OptiX, CUDA, HIP, oneAPI) when present, else CPU. Contact sheets render only
  the beat-grid frames at half size; alpha films deliver ProRes 4444 / WebM alpha from RGBA frames.
  Skill `fcwm-blender`; draft and determinism check in the smoke test (a full render is too slow on CI).
- Brand kits (optional, none shipped): `fcwm brand init | check | list` keeps a user's kit in
  `~/.fcwm/brand-kits/<kit>/` (schema `brand-kit/brand-kit.schema.json`); `fcwm new <film> --brand <kit>`
  copies it into the film, links `brand/brand.css` (colours, fonts) in HyperFrames films, and the Manim
  and Blender starters read its colours.
- Film blocks: `lib/blocks.js` (transitions: cut, fade, dip, wipe, push, slide, zoom, iris; title card;
  lower third; word-timed captions; end card; `css(state)`), tested, and the `film-blocks` recipe that
  uses all of them (render and QA pass).
- Lottie and animated SVG (experimental), as a HyperFrames route: `fcwm new <film> --lottie
  [animation.lottie|.json]` plays the user's animation on a canvas seeked by HyperFrames (no autoplay,
  no own clock). The player is dotlottie-web 0.82.0 (MIT), fetched once from npm into `~/.fcwm/cache`
  and copied with its LICENSE into the film, so renders read only local files; `--alpha` works.
  Animated SVG is written inline and driven from `renderAt(t)`. No Lottie or SVG file export.
  Guide: `skills/fcwm-hyperframes/references/lottie-svg.md`. Lottie added to the smoke test.
- Manim engine (experimental): Manim Community 0.22.1 (MIT) through `uv run --with`, pinned, not
  vendored. `fcwm new <film> --engine manim` starts from a brand-neutral, LaTeX-free scene; films may
  list several formats (each rendered on its own canvas); `--alpha` delivers ProRes 4444 / WebM alpha.
  Contact sheets and stills are cut from a draft render with ffmpeg. `fcwm setup` installs Pango and
  Cairo headers on Linux. Skill `fcwm-manim`; Manim added to the smoke test.
- `fcwm new <film> --3d` starts from a real 3-D film: a neutral stage (`sets/stage.js`, three primitives
  dropping on the beat, orbiting camera, soft shadows) under a 2-D title, in every format. The motion-reel
  starter's placeholder copy is neutral now, and its headline no longer leaves blank frames before the
  second scene (QA failed every starter film of 4 s or more). A failed render in GitHub Actions now
  uploads its files under the film's name.
- Extra delivery formats: `fcwm render <film> --export gif,webm,mov` (or `"exports"` in film.json)
  transcodes the delivered MP4 to GIF, WebM VP9 and ProRes 422 HQ. Transparency: `fcwm new <film>
  --alpha` starts a HyperFrames film on a transparent ground and renders `mov-alpha` (ProRes 4444) or
  `webm-alpha` (VP9 with alpha) straight from the engine. QA checks every export exists, has the right
  size, and that alpha exports really carry an alpha channel.
- No renders for pull requests from forks: the `smoke` and `install` jobs skip unless the pull request
  comes from a branch of this repository; fork pull requests get only `validate` (no browser, no ffmpeg).
  `npm run validate` fails if a rendering job loses that guard or any workflow uses
  `pull_request_target`. Maintainer settings to click: `docs/render-in-github-actions.md`.
- Path-traced 3-D quality mode on motion-reel (experimental): `fcwm new <film> --pathtrace` traces the
  same three.js sets with three-gpu-pathtracer 0.0.27 (MIT) for real reflections, glass, soft area
  light shadows and depth of field. Fixed samples per frame, seeded sequences, motion-blur sub-frames
  share the budget; `--spp`, `--pt-scale`, `--draft` on the renderer, low-sample contact sheets,
  one worker. Listed as a `modes` entry on motion-reel in `engines/catalog.json` (validated). A
  determinism and non-black test frame runs in the smoke workflow. Guide: `references/pathtrace.md`.
- The motion-reel renderer serves `/node_modules/` from the FCWM install when the films folder has
  none, so 3-D films need no npm step of their own (three, opentype.js and the path tracer are pinned in
  FCWM's `package.json`).
- Render hand-off for any agent: one self-contained film folder, its path, one command.
  `scripts/install.sh` (macOS, Linux) and `scripts/install.ps1` (Windows) install Node.js and FCWM only
  when missing, then `fcwm run <folder>` installs only the tools the film lacks and renders into
  `<folder>/render/`. Every run re-detects tools and records them in `~/.fcwm/state.json`; the run
  prints the short command for next time.
- `fcwm run`, `fcwm setup`, `fcwm command` (the exact line per OS, quoted for any path).
- `fcwm run --cloud`: renders in GitHub Actions on the user's own account (private `fcwm-renders`
  repository via the GitHub CLI) and downloads the result into the same folder. Workflow template
  `templates/cloud-render/fcwm-render.yml`; by-hand browser steps in `docs/render-in-github-actions.md`.
- motion-reel writes its intermediate files to `<film>/.fcwm/out` (`MOTION_REEL_OUT`), so nothing lands
  outside the film folder. Films record the FCWM version in `film.json` (`fcwm`).
- Skill reference `skills/fcwm/references/handoff.md`; docs `render-on-your-computer.md`.
- Workflow `install`: the installers on Linux, macOS and Windows in a path with a space, `&` and `'`.

## 0.2.0 (unreleased)

- `scripts/fcwm.mjs`: cross-platform CLI (`new`, `render --check/--at`, full render with mix and phone
  preview, `qa --determinism`, `doctor`, `engines`, `--dry-run`), replacing the zsh starter scripts.
- Engines: motion-reel 1.3.0 vendored (MIT) with an adapter; HyperFrames 0.8.226 through pinned npx with
  telemetry off and a brand-neutral, GSAP-free starter (`templates/hyperframes-blank`).
- Automated QA after every render (`qa/checks.mjs`): loudness and true peak, constant fps, canvas size,
  flat frames, byte-identical re-renders; report in `render/qa.json`.
- Skills: engine router and quick/full modes in `fcwm`, engine skills `fcwm-hyperframes` and
  `fcwm-motion-reel`, references copied into each skill (`scripts/sync-skill-refs.mjs`, checked by
  validate).
- Workflows: `smoke` (one film per engine on every PR), `render` (manual cloud render), Node 22.
